4) ข้อบกพร่อง 15 ข้อ: ก่อนแก้ / หลังแก้
--------------------------------------------------
[1] (P1) ร้านเสนอข้อมูลแบบประโยคบอกเล่า แล้วถูกนับเป็นยอดขาย
    ตัวอย่าง:
      "ส่งแคตตาล็อกให้ได้นะครับ" / "เอาครับ"
    ก่อน: ยืนยันยอดขาย
    หลัง: เป็นการตอบรับข้อมูล ไม่นับเป็นยอดขาย
          ถ้าในข้อความมีราคาหรือคำว่าสั่งซื้อด้วย -> ให้คนตรวจ

[2] (P1) ปฏิเสธการซื้อชัดเจน แต่ยอดขายยังค้างอยู่
    ตัวอย่าง:
      ตกลงซื้อแล้ว -> ร้านเสนอแคตตาล็อก -> ลูกค้า "ไม่ซื้อครับ"
    ก่อน: ยอดขายยังยืนยันอยู่
    หลัง: ดีลถูกปฏิเสธ (declined)
          ส่วน "ไม่เอาครับ" ที่ตอบเรื่องแคตตาล็อก ยังถือว่าปฏิเสธแค่แคตตาล็อก

[3] (P2) ส่งราคาในแชต ถูกนับว่าส่งใบเสนอราคาแล้ว
    ตัวอย่าง:
      ลูกค้าขอ PDF / ร้าน "ส่งราคาให้แล้วครับ 18500 บาท"
    ก่อน: ปิดคำขอใบเสนอราคา
    หลัง: เป็น price_sent
          คำขอใบเสนอราคายังเปิดอยู่จนกว่าจะส่งเอกสารจริง

[4] (P2) "ถ้าติดตั้งเสร็จแล้วจะโทรแจ้ง" ถูกนับว่าติดตั้งเสร็จ
    ก่อน: ปิดคำรับปากการติดตั้ง
    หลัง: ต้องเป็นการรายงานว่าเสร็จจริงเท่านั้น
          ไม่นับประโยคเงื่อนไข / อนาคต / คาดเดา / ปฏิเสธ / คำถาม

[5] (P2) เลื่อนการโอนมัดจำ ถูกนับเป็นการเลื่อนนัดติดตั้ง
    ตัวอย่าง:
      "ขอเลื่อนโอนมัดจำไปวันศุกร์"
    ก่อน: นัดติดตั้งถูกยกเลิก และขอเวลานัดใหม่
    หลัง: เป็นการเลื่อนการชำระเงิน นัดติดตั้งไม่เปลี่ยน
          รองรับกรณีเลื่อนทั้งสองอย่างในข้อความเดียวด้วย

[6] (P2) "เอาครับ แต่ยังไม่ต้องส่ง" แต่ระบบเสนอให้ส่งทันที
    ก่อน: เสนอ action ส่งข้อมูลทันที
    หลัง: บันทึกการตอบรับพร้อมเงื่อนไข (deferred)
          เสนอ "รอให้ลูกค้าแจ้งก่อน" แทน

[7] (P1) เบอร์โทร +66890000000 กลายเป็นรายได้ 66,890 ล้านบาท
    ก่อน: นับเป็นโอกาสรายได้
    หลัง: ไม่ใช่จำนวนเงิน
          ตัวเลขที่ไม่มีคำบ่งชี้ราคา จะนับเฉพาะเมื่อข้อความตอบกลับเป็นแค่ราคาเท่านั้น

[8] (P2) มูลค่าของแถม / ค่าแรงที่รวมในราคา / ค่าใช้จ่ายของร้าน แทนที่ราคาขาย
    ก่อน: โอกาสรายได้เป็น 500 หรือ 1,500 บาท
    หลัง: แยกประเภทเป็นของแถม / ส่วนประกอบ / ค่าใช้จ่าย ไม่นับเป็นรายได้
          ยอดรวมเดิมยังคงอยู่ และมีคำเตือนให้ตรวจ

[9] (P2) "ช่างบอกราคา 18500 บาท" ถูกนับเป็นงบลูกค้า
    ก่อน: ตัวอักษร "งบ" อยู่ในคำว่า "ช่างบอก"
    หลัง: นับเป็นงบเฉพาะเมื่อเป็นคำว่า "งบ" จริง

[10] (P2) "15 ต.ค. 70" ปี 70 หายไป แล้วถูกแปลงเป็นปี 2026
    หลัง: เก็บข้อความเต็ม "15 ต.ค. 70"
          ไม่แปลงวันที่ เพราะปีกำกวม

[11] (P2) คำถามเกี่ยวกับใบเสนอราคา ถูกนับเป็นคำขอ
    ตัวอย่าง:
      "ไม่ต้องส่งใบเสนอราคา"
      "ใบเสนอราคามีอายุกี่วัน"
      "ได้รับใบเสนอราคาแล้ว"
    หลัง: แยกเป็น ปฏิเสธ / คำถาม / แจ้งว่าได้รับ
          ไม่สร้าง action ส่ง และไม่เปลี่ยนสถานะดีล

[12] (P2) คำพูดของเพื่อนยกเลิกดีลของลูกค้า
    ตัวอย่าง:
      "เพื่อนบอกว่าไม่เอาแล้ว แต่ผมยังเอาตามเดิม"
    ก่อน: ดีลถูกยกเลิก
    หลัง: ยอดขายยังอยู่
          ถ้าไม่มีการยืนยันซ้ำ -> ให้คนตรวจ แต่ไม่ยกเลิก

[13] (P2) ผู้พูดไม่ทราบตัวตน แต่ signal ที่ระบบสร้างต่อมีความมั่นใจสูงขึ้น
    ก่อน: ความมั่นใจ 0.84
    หลัง: ไม่เกิน 0.65 และไม่สูงกว่าแหล่งที่มา

[14] (P2) Signal ID ของ adapter ภายนอกชนกับ ID ที่ระบบสร้าง
    หลัง: ID ไม่ซ้ำกัน
          ตรวจความถูกต้องของผลลัพธ์สุดท้ายทั้งหมดอีกครั้ง

[15] (P2) ลูกค้าบอกว่าที่อยู่ผิด แต่ระบบยังถือว่ามีที่อยู่แล้ว
    หลัง: ขอที่อยู่ใหม่ จนกว่าจะได้รับที่อยู่ใหม่

ข้อควรระวัง (สำคัญ):
- ตัวเลขข้างบนไม่ใช่ blind เพราะปรับกฎหลังดูข้อผิดพลาดของทุกชุดแล้ว
- รอบแรกของ holdout4 (ล็อก label ก่อนรัน):
    คำรับปาก 0.667 (ต่ำกว่าเป้า มีเพียง 4 รายการ)
    จำนวนเงิน 1.000
    วันที่ 1.000
    รอตัดสินใจ 1.000
    ยอดขาย 0.750
    ยืนยันขายผิด 0/15
  ข้อผิดพลาดทั้งหมดเป็นฝั่ง "ระวังเกินไป"
  เช่น ไม่ยืนยันยอดขายจริง หรือพลาดคำรับปากนัด
  ไม่มีการนับยอดขายผิด
- ขายผิด 0 จาก 116 บทสนทนา:
  ถ้าสุ่มแบบ IID ขอบบน 95% จะอยู่ราว 2.6%
  แต่ข้อมูลนี้ถูกเลือกมาและใช้ปรับกฎแล้ว
  จึงยังพิสูจน์ไม่ได้ว่าต่ำกว่า 3% จริง
- benchmark วัดเฉพาะ label / เงิน / วันที่ / ค่าจริง-เท็จ
  ไม่ได้วัดเรื่องสิทธิ์ของรายได้ การปิดคำรับปาก หรือการขอเลื่อน
  เรื่องเหล่านี้ตรวจด้วย regression test และสคริปต์ 28 ข้อของผู้รีวิว
- ยังไม่ได้วัดความมีประโยชน์ของ action โดยคน


6) จุดอ่อนที่ยังเหลือ
--------------------------------------------------
- การตีความ "อะไร" และ "จริงหรือไม่" ยังเป็นกฎ pattern ภาษาไทย ไม่ใช่ parser
  การรีวิวแต่ละรอบยังพบกรณีข้างเคียงใหม่
- การแยกประเภทเงินยังเป็น heuristic
  * ตัวเลขติดกัน 9 หลักขึ้นไปถือเป็นรหัส/เบอร์เสมอ
    ราคาที่ใหญ่ขนาดนั้นต้องเขียนพร้อมจุลภาค เช่น 150,000,000
  * ราคาที่ความสัมพันธ์กับยอดรวมไม่ชัด -> คงยอดรวมไว้และให้คนตรวจ
    ระบบไม่ตัดสินเอง
- ยังรองรับนัดเดียวต่อดีล และหนึ่งดีลต่อหนึ่งบทสนทนา
- ใช้ข้อมูลสังเคราะห์เท่านั้น
- ค่า confidence ยังไม่ได้ calibrate


7) ขั้นตอนถัดไปที่แนะนำ
--------------------------------------------------
1. หยุดเพิ่มกฎจากกรณีสังเคราะห์
2. ล็อกชุดทดสอบจากแชตจริงที่ได้รับอนุญาตและลบข้อมูลส่วนตัวแล้ว
   ก่อนแก้กฎใดๆ
3. ให้คนให้คะแนนความมีประโยชน์ของ action
4. หลังจากนั้นจึงพิจารณาเสริมโครงสร้างความหมาย
   เช่น LLM extractor ผ่าน interface เดิม
   โดยใช้ด่านตรวจผลลัพธ์สุดท้ายแบบเดิม
