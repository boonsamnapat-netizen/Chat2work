3) ปัญหา 13 กลุ่ม: ก่อนแก้ / หลังแก้
--------------------------------------------------
P1-01 ตอบรับแบบไม่แน่ใจ
  เคส: "เอาครับ มั้งนะ", "เอาครับ น่าจะเอานะ", "ตกลงซื้อเลยครับมั้ง"
  ก่อน: ยืนยันการขาย
  หลัง: possible_acceptance (ไม่ใช่การขาย), ต้องรีวิว, เสนอ confirm_deal_status พร้อมหลักฐาน
  ตัวควบคุม: "ยืนยันตามราคานี้ครับ" ยังนับเป็นการขาย

P1-02 เงื่อนไขที่จบในตัวไม่ควรบังการยกเลิก
  เคส: "ถ้าใบเสนอราคาส่งไม่ทันไม่เป็นไร ผมยกเลิกงานนี้ครับ"
  ก่อน: ยังนับเป็นการขาย
  หลัง: ยกเลิก (cancelled) โดยเก็บหลักฐานทั้งการตอบรับและการยกเลิก
  ตัวควบคุม: "ถ้าลดได้ เอาครับ" ยังไม่นับเป็นการตอบรับ

P1-03 คำพูดของคนอื่นไม่ควรบังการปฏิเสธของลูกค้าเอง
  เคส: "เพื่อนบอกว่าดี แต่ผมไม่ซื้อครับ"
  ก่อน: ยังนับเป็นการขาย
  หลัง: declined
  ตัวควบคุม:
  - "เพื่อนบอกว่าไม่เอาแล้ว" ยังเป็นแค่ต้องรีวิว
  - "...แต่ผมยังเอาตามเดิม" การขายยังอยู่

P2-01 ไม่เลื่อน / อาจจะเลื่อน
  เคส: "ไม่เลื่อนนัด", "อาจจะเลื่อนนัด", "ไม่เลื่อนวันที่โอนมัดจำ"
  ก่อน: ยกเลิกนัดเดิม ถามเวลาใหม่ หรือเสนอเปลี่ยนวันชำระ
  หลัง: นัดเดิมยังอยู่ ไม่เปลี่ยนวันชำระ
        "อาจจะเลื่อน" ให้ possible_reschedule เพื่อถามให้ชัด
  ตัวควบคุม: การเลื่อนจริงยังทำงาน, เลื่อนวันโอนไม่กระทบนัดติดตั้ง

P2-02 ส่งของแล้วต้องตรงกับสิ่งที่ส่ง
  เคส: "ส่งรูปให้แล้วครับ ส่วนใบเสนอราคาจะส่งพรุ่งนี้"
       และ "ส่งราคาให้แล้วครับ ใบเสนอราคาจะส่งพรุ่งนี้"
  ก่อน: ปิดงานใบเสนอราคา
  หลัง: ใบเสนอราคายังค้าง มี send_quotation และติดตามคำรับปาก "พรุ่งนี้"
  ตัวควบคุม: ส่งเอกสารจริงจึงปิด

P2-03 การชำระเงิน: วัตถุประสงค์ / ยอดซ้ำ / จ่ายไม่ครบ
  - "โอนค่าอะไหล่ 5000 บาทแล้ว มัดจำยังค้างอยู่"
      มัดจำยังค้าง เพราะเป็นค่าอะไหล่ ไม่ใช่มัดจำ
  - "โอน 1000 บาทแล้ว ยอดเดียวกับเมื่อกี้"
      ไม่นับซ้ำ มัดจำ 2000 ยังค้าง (จ่ายแล้ว 1000)
  - "โอนแล้วครับ แต่ยังไม่ครบ"
      ยังติดตาม และไม่เดายอดคงเหลือ
  ตัวควบคุม:
  - โอนเพิ่มอีก 1000 นับแยกเป็นยอดใหม่
  - โอนครบปิดคำรับปาก แต่ยังต้องตรวจยอดจริง

P2-04 ช่างมาถึง ≠ งานเสร็จ
  เคส: "ช่างมาถึงแล้วครับ ยังไม่ได้เริ่มติดตั้ง"
  ก่อน: ปิดงานติดตั้ง
  หลัง: technician_arrived และงานติดตั้งยังติดตามอยู่
  ตัวควบคุม: "ติดตั้งเสร็จแล้ว" จึงปิด; เสร็จแบบปฏิเสธ / มีเงื่อนไข / ไม่แน่ใจ ไม่ปิด

P2-05 เวลาต้องเป็นของเหตุการณ์ที่ถูก
  เคส: นัดติดตั้งวันเสาร์ แล้วลูกค้าบอก "ว่างคุยโทรศัพท์วันนี้ 18:00"
  ก่อน: นับ 18:00 เป็นเวลาติดตั้ง
  หลัง: เวลานี้เป็นเวลาคุยโทรศัพท์ จึงยังถามเวลาติดตั้ง

P2-06 ราคาร้านอื่นไม่ใช่โอกาสรายได้ของเรา
  เคส: "ร้านอื่นราคา 18500 บาทครับ ร้านผมยังไม่ได้คิดราคา"
  ก่อน: โอกาส 18,500
  หลัง: competitor_price, โอกาส = null, คำถามราคายังต้องตอบ
        ราคาร้านเราที่ให้ทีหลังจึงเป็นยอดโอกาส

P2-07 ตรวจค่าจาก extractor / adapter
  - เพิ่ม chat2work/validation.py ตรวจชนิดและค่าก่อนนำไปคำนวณ
  - ยอดเงินต้องเป็นทศนิยมบวกที่จำกัด, มีสกุลเงิน, role, วันที่ และการอ้างอิงที่ถูกต้อง
  - ค่าผิด (-1000 USD, NaN, Infinity, {}) แจ้ง ValueError ที่ชัดเจน
    ไม่ล่มด้วย KeyError และไม่สร้างรายได้ปลอม
  - ไม่เปลี่ยน USD เป็น THB
  - adapter ส่ง acceptance 0.99 กับ "ขอคิดดูก่อนครับ"
    ก่อน: ยืนยันการขาย
    หลัง: acceptance_needs_review + confirm_deal_status พร้อมหลักฐาน
  - แก้ README: หลักฐานตรงและความมั่นใจสูงไม่ได้พิสูจน์ความหมาย

P2-08 การปิดบังข้อมูลต้องไม่เปลี่ยนผล
  เคส: แทนลิงก์แผนที่ด้วย [ที่อยู่]
  ก่อน: ระบบถามที่อยู่ใหม่
  หลัง: นับว่ามีที่อยู่แล้ว (chat2work/redaction.py)
        มี test ยืนยันว่าผลเหมือนเดิมก่อนและหลังปิดบัง ที่อยู่ เบอร์ ชื่อ และบัญชี

P2-09 ตัวชี้วัด pilot (PILOT_EVALUATION_PLAN.md)
  - usefulness = useful ÷ ทั้งหมดที่ให้คะแนน
  - correctness = (useful + correct-but-not-needed) ÷ ทั้งหมดที่ให้คะแนน
  - นับ wrong และ harmful แยก
  - นับ action ที่ควรเสนอแต่ไม่ได้เสนอ
  - วัดเวลารีวิว / แก้ไข
  - กำหนดตัวหารและการจัดการรายการที่ไม่ได้ให้คะแนนไว้ล่วงหน้า
  - ห้ามอ้าง ≥80% ถ้ายังไม่มีคะแนนจากคน
  - แนะนำเริ่ม pilot แบบมีคนกำกับในธุรกิจแอร์ก่อน

P2-10 การประเมินที่เข้มขึ้น
  - ตรวจคำรับปากที่ค้างตาม ผู้รับผิดชอบ / ยอด / วัตถุประสงค์ / สิ่งของ / กำหนดเวลา
  - safety scenarios ใหม่ 28 เคส ลงโทษกรณี:
    ปิดผิดสิ่ง, นับยอดโอนซ้ำ, วัตถุประสงค์การชำระผิด, เวลาของเหตุการณ์อื่น
  - gate ใหม่: การขายจริงที่ตกหล่นโดยไม่ส่งรีวิวต้องเป็น 0 ทุกชุด

5) จุดอ่อนที่ยังเหลือ
--------------------------------------------------
- "เพื่อนบอกว่าร้านนี้ดี ผมเอาครับ" (ไม่มี "แต่") ยังไม่นับเป็นการตอบรับ และไม่ส่งรีวิว
- "คงไม่เอาครับ" (ปฏิเสธแบบไม่แน่ใจ) ยังไม่ถูกจับ
- ยอดโอนซ้ำจับได้เฉพาะเมื่อมีคำอย่าง "ยอดเดิม / ยอดเดียวกับเมื่อกี้"
- วัตถุประสงค์การชำระดูจาก "มัดจำ" หรือ "ค่า..." เท่านั้น
- "โทรมาก่อนเข้า 10:00" ถูกมองเป็นเวลาโทร จึงถามเวลานัดซ้ำ (ระวังไว้ก่อน)
- งานสำรวจที่บอกแค่ "ช่างเข้ามาดูหน้างานแล้ว" ยังค้างให้ติดตาม
- ราคาร้านอื่นจับได้เฉพาะคำว่า ร้านอื่น / เจ้าอื่น / ที่อื่น / คู่แข่ง
- การตรวจ acceptance ของ adapter ใช้กฎภาษาไทยชุดเดียวกัน
  ถ้าเป็นถ้อยคำที่กฎอ่านไม่ออก ระบบก็ยังเชื่อ adapter
