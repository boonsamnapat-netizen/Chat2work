2) Chat2Work คืออะไร
--------------------------------------------------
Engine ภาษาไทยสำหรับธุรกิจบริการขนาดเล็ก
(แอร์ กล้องวงจรปิด ไฟฟ้า ซ่อม รับเหมา โรงพิมพ์ ฟรีแลนซ์ออกแบบ เอเจนซี โซลาร์ ตกแต่งภายใน)

อ่านแชตลูกค้า–ร้าน แล้วตอบเป็น JSON ว่า:
  เกิดอะไรขึ้น / ใครรับปากอะไร / มีเงินเกี่ยวข้องตรงไหน / ควรทำอะไรต่อ

ทุกข้อมูลที่ดึงออกมามีหลักฐานกำกับ:
- ข้อความต้นฉบับ
- หมายเลขข้อความ
- ผู้พูด
- ความมั่นใจ

ขอบเขตการทำงาน:
- เป็น intelligence engine ไม่ใช่ CRM หรือ chatbot
- ไม่ส่งข้อความ ไม่ดำเนินการเอง ไม่เก็บแชต
- ทุก action เป็น "ข้อเสนอ" ที่ต้องให้คนอนุมัติก่อน
- ใช้กฎ (rule-based) ไม่ต้องใช้ API key และไม่มี dependency ภายนอก
- รองรับ adapter ของ OpenAI / Gemini / Claude / Ollama ในอนาคตผ่าน Extractor interface เดียวกัน


3) สิ่งที่พบจากการตรวจ ZIP ที่แนบมา
--------------------------------------------------
- รันซ้ำได้ตรงตามที่อ้าง: 113 tests ผ่าน และ benchmark 100%
- แต่ชุดข้อมูลนั้นเขียนมาคู่กับกฎ จึงไม่ใช่การวัดแบบ blind
  ตัวอย่างที่ใช้วัดน้อยมาก: คำรับปาก 8 รายการ, วันที่ 10 รายการ, ยอดขาย 6 รายการ
- จึงเขียนชุดทดสอบใหม่ 35 บทสนทนาก่อนรัน engine
  รอบแรกพบปัญหาจริง:
  * ร้านถาม "ส่งแคตตาล็อกให้ดูไหม" ลูกค้าตอบ "เอาครับ" -> ระบบนับเป็นยอดขาย
    (ขายผิด 1/29 = 3.4% เกินเป้า 3%)
  * "เดี๋ยวโอน 18:00" ถูกอ่านเป็นเงิน 18 บาท
  * "ไม่สนใจ" ถูกนับเป็นความสนใจ
  * "ยกเลิกนัด... เลื่อนเป็นวันศุกร์" ถูกนับเป็นยกเลิกดีล
  * ไม่จับ "15 ต.ค.", "เสาร์นี้" และคำว่าขอคิดก่อนบางแบบ


4) สิ่งที่แก้ไข (24 จุด ทุกจุดมี regression test)
--------------------------------------------------
- ความปลอดภัยด้านยอดขาย
  * "เอาครับ" ที่ตอบคำถามซึ่งไม่ใช่การซื้อ -> "possible_acceptance" (ให้คนตรวจ) ไม่นับเป็นยอดขาย
  * "ok ครับ / ตกลงครับ" หลังร้านแจ้งราคา -> "possible_acceptance" เช่นกัน
- เงิน
  * ไม่อ่านเวลา วันที่ หรือเบอร์โทรเป็นเงิน
  * แก้บั๊กคำไทยซ้อน: "งบ" ใน "ทั้งบ้าน" เคยทำให้ราคาร้านกลายเป็นงบลูกค้า
  * แยกประเภท: ราคา / ยอดรวม / มัดจำ / งบ / ราคาต่อหน่วย / ยอดคงเหลือ / ส่วนลด / การโอน
- วันที่
  * รองรับ "15 ต.ค.", "เสาร์นี้", "บ่าย 2", "2 ทุ่ม", "10.30 น.", "เดือนหน้า"
  * --reference-date ใช้แปลงวันที่สัมพัทธ์ แปลงเฉพาะที่ไม่กำกวม
  * ถ้าไม่ใส่ --reference-date ทุก resolved_date จะเป็น null
- สถานะดีล
  * ยกเลิก / ปฏิเสธ / เปลี่ยนใจ / ร้านยกเลิก แยกชัดเจน
  * ถ้าข้อความเดียวมีหลายสัญญาณ ให้สัญญาณที่หนักแน่นกว่าชนะ
  * ดีลที่ยกเลิกแล้วเสนอ action "confirm_cancellation"
- ข้อมูลที่ขาด (ตามบริบท)
  * ขอที่อยู่/เวลาเฉพาะเมื่อมีการนัดงานหน้างานจริง
  * ขอ agreed_price เมื่อลูกค้าตกลงแต่ไม่มีราคาเดียวที่ชัดเจน
- การอ่านแชต
  * รองรับ timestamp, ไฟล์ export แบบ tab, รูปแบบ "ลูกค้า (ชื่อ):"
  * map ชื่อผู้พูดเองได้ด้วย --customer / --business


5) ผลวัด (บทสนทนาสังเคราะห์ 107 ชุด, 10 อุตสาหกรรม + แชตทั่วไป)
--------------------------------------------------
                         ชุดเดิม(46)  ชุดทดสอบ1(35)  ชุดทดสอบ2(26)  เป้า
คำรับปาก (F1)            1.000        1.000          1.000          >= 0.90
จำนวนเงิน (F1)           1.000        1.000          0.982          >= 0.95
วันที่/นัดหมาย (F1)       1.000        1.000          1.000          >= 0.90
ยืนยันขายผิด             0/40         0/29           0/19           < 3%

ข้อควรระวัง (สำคัญ):
- ตัวเลขข้างบนไม่ใช่ blind เพราะปรับกฎหลังดูข้อผิดพลาดของทั้งสองชุดแล้ว
- ตัวเลขที่ซื่อตรงกว่าคือรอบแรกของชุดทดสอบ 2 ก่อนแก้ (data/blind_first_runs.json):
  * คำรับปาก 0.800 (ต่ำกว่าเป้า)
  * วันที่ 0.706 (ต่ำกว่าเป้า)
  ควรคาดว่าแชตจริงจะได้ผลต่ำกว่านี้
- ขายผิด 0 จาก 88 ยังพิสูจน์ไม่ได้ว่าต่ำกว่า 3% จริง (ขอบบน 95% ประมาณ 3.4%)
- ยังไม่ได้วัดความมีประโยชน์ของ action โดยคน (เป้า >= 80%) ในรายงานเป็น null
- ค่า confidence เป็นค่าที่ตั้งเอง ไม่ใช่ความน่าจะเป็นที่ calibrate แล้ว
  >= 0.90 = high
  0.80–0.89 = medium
  < 0.80 = ต้องให้คนตรวจ


6) จุดอ่อนที่ยังเหลือ
--------------------------------------------------
- กฎรู้จักเฉพาะสำนวนที่เขียนไว้
  ภาษาพูด สะกดผิด ภาษาถิ่น อาจพลาด
- เลือกพลาดยอดขายดีกว่าสร้างยอดขายปลอม
  เช่น "เอาครับ เดี๋ยวโอนก่อน" จะยังไม่นับเป็นการขาย
- รองรับหนึ่งดีลต่อหนึ่งบทสนทนา
  ยังไม่รองรับหลายงาน ยกเลิกบางส่วน หรือคืนเงิน
- ข้อความหลายบรรทัดที่ไม่มีชื่อผู้พูดจะถูกนับเป็นผู้พูดไม่ทราบตัวตน
- จำนวนเงินแบบย่อจะไม่ถูกดึงเลย แทนที่จะดึงผิด
  เช่น "2.5k", "หมื่นแปดห้า"
- ราคาคู่แข่งที่ไม่มีคำบ่งชี้จะพลาด
  เช่น "อีกร้านให้ 13,500"


7) งานที่แนะนำสำหรับ v0.2
--------------------------------------------------
1. เก็บแชตจริงที่ได้รับอนุญาตและลบข้อมูลส่วนตัวแล้ว
   ล็อกชุดทดสอบก่อนปรับกฎ
   ให้คนให้คะแนนความมีประโยชน์ของ action
2. เพิ่ม adapter AI (Claude/OpenAI/Gemini/Ollama) ผ่าน Extractor เดิม
   ใช้การตรวจหลักฐานและด่านยืนยันการขายเดิม
3. Calibrate ค่า confidence และสร้างขั้นตอนตรวจ/อนุมัติ (ยังไม่ execute)
4. รองรับหลายดีลในแชตเดียว ยกเลิกบางส่วน แก้ใบเสนอราคา คืนเงิน
5. ใช้ timestamp จริงของข้อความ + timezone Asia/Bangkok
6. ขยายภาษาไทย: ตัวเลขแบบคำ ตัวย่อ คำสแลง


8) วิธีใช้งาน
--------------------------------------------------
git clone -b claude/chat2work-core-v0-1-nvtlab https://github.com/boonsamnapat-netizen/Chat2work.git
cd Chat2work
python -m venv .venv
source .venv/bin/activate          (Windows: .venv\Scripts\activate)
pip install -e '.[dev]'

chat2work data/example_conversation.txt
chat2work data/example_conversation.txt --reference-date 2026-10-07
printf 'ลูกค้า: สนใจครับ\nร้าน: ราคา 18,500 บาท\nลูกค้า: ขอคิดดูก่อน\n' | chat2work

python -m pytest -q
python evaluate.py --check

รูปแบบแชต: หนึ่งข้อความต่อบรรทัด เช่น
  ลูกค้า: ...
  ร้าน: ...
